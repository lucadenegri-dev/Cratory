## A) Migliorie funzionali

### Alta priorità

- **A1 · Export set non chiude il flusso** — `routers/sets.py:153-209` produce solo
  testo inline mostrato in un `<pre>` (icona Download che non scarica nulla). Con il
  disk-first completo, un set "solo posseduti" ha tutti i `local_path` ma nessun
  formato li usa. Proposta: `format=m3u` (#EXTM3U con local_path), `local_path` nel
  CSV, e in UI "Copia" + download reale via Blob.
- **A2 · Tracklist Shazam vicolo cieco** — `shazam/[id]` è read-only: niente
  cross-match con la libreria né azioni, nonostante ISRC persistito su `DjSetTrack` e
  dedup/`discovery/add` già pronti. Proposta: badge IN LIBRERIA/POSSEDUTA/NUOVA per
  riga + "Salva in libreria" (+"Salva tutte le nuove").
- **A3 · 5 strategie del Set Builder su 7 sono un no-op** — `set_generator.py:28-36`:
  solo peak_time e warm_up cambiano la curva; contrast/experimental/closing/progressive
  ≡ smooth. Dare semantica reale o toglierle dalla UI.
- **A4 · Scoring BPM senza half/double-time e con soglie assolute** —
  `scoring.py:199-209`: 85→170 vale 5/50 punti (è un mix half-time perfetto); ±8 BPM
  fissi non scalano col tempo. Proposta: `min(|a-b|, |a*2-b|, |a/2-b|)` + soglie in %.
- **A5 · Ranking delle 60 candidate AI degenere senza seed/start_bpm** —
  `ai_agent.py:108-122`: con solo prompt libero l'AI riceve "le prime 60 del DB".
  Proposta: ranking multi-segnale + campionamento stratificato su BPM/key.
- **A6 · Gap analysis di libreria: endpoint morto + mai in UI** — `/api/playlists/library/gaps`
  è registrato DOPO `/{playlist_id}/gaps` → 422 sempre (`routers/playlists.py:294` vs `:282`).
  Fix: spostare la registrazione prima + mostrare le lacune in dashboard.
  (Nota: il client `libraryGaps` è stato rimosso come codice morto — reintrodurlo col fix.)
- **A7 · Download manuale: possesso non marcato se il dedup ISRC fonde su una traccia
  esistente** — `soulseek_download_job.py:150-161` cerca solo `platform='local_files'`;
  se il file taggato ISRC matcha una Track Spotify, `attach_local_file` non parte mai:
  file in inbox, `has_local_file=False`, job conta "downloaded". Risolvere con la
  stessa catena di identità del dedup.

## E) Migliorie tecniche

### Database e core (backend)

- **E1 · Schema**: (a) `ensure_schema` non crea mai gli indici del modello sui DB
  esistenti — sul DB live mancano 5 indici su `tracks` (`archived`, `audio_hash`,
  `has_local_file`, `mbid`, `album_id`) usati nelle query calde; fix: iterare
  `Base.metadata` e `idx.create(checkfirst=True)`. (b) Nessun PRAGMA: WAL +
  busy_timeout + foreign_keys via listener 'connect' (job concorrenti = "database is
  locked" concreto; FK OFF = orfani che la pulizia manuale in db.py:162 già tampona).
  (c) Migrazioni a dict manuale → derivarle dal modello via inspector. (d)
  `EnrichmentCache` senza `UniqueConstraint(provider, lookup_key)` (righe duplicate
  possibili da job paralleli). (e) N+1 su `Track.playlists` in setlist/transitions/
  download-pending → 3 selectinload.
- **E2 · Resilienza job**: commit unico a fine run in `enrich_features` e
  `fingerprint_tracks` — un'interruzione perde ore di lookup rate-limited, cache
  inclusa → commit ogni ~20 tracce. `index_library`: transazione unica + stat() senza
  guardia per-file → un file sparito a metà scan butta tutti gli hash. Stato job
  condiviso restituito con copia shallow → race sulla serializzazione di /status.
- **E3 · Cache enrichment** (il tema più impattante): errori transitori dei provider
  cacheati come esiti definitivi (503 MusicBrainz → "not found" per sempre senza
  force); Deezer quota (code 4) indistinguibile da "non trovato" (code 800); nessun
  TTL; chiave 'chain' cieca alla composizione (aggiungi Last.fm dopo → cache vecchia
  vince). Fix: annotare `_errors` nel merged, non cachearli (policy già scritta in
  fingerprint.py), TTL per i not-found, firma della catena nella chiave.
- **E4 · Regola "manual resta autorevole" violabile**: `_apply_features` sovrascrive
  sempre source/confidence anche per apporti metadata-only → traccia manual/100 può
  degradare a low_confidence; `update_track` marca manual/100 anche azzerando un
  campo. Aggiornare source/confidence solo sui campi core e mai sopra 'manual'.
- **E5 · Spotify**: il 401 cancella l'intera riga token (refresh_token incluso) →
  re-login forzato; azzerare solo l'access token. `Retry-After` parse senza guardia.
- **E6 · slskd**: nessuna cancel dei transfer abbandonati (fino a 4 download attivi
  dello stesso brano, orfani in inbox); match per solo filename sul log storico (esiti
  falsi al retry); ricerche mai cancellate dal daemon; risoluzione file per
  basename+mtime (rischio file sbagliato); fino a ~45s di attesa sincrona su
  /candidates.
- **E7 · Indicizzazione**: fuzzy match può "rubare" la traccia a un file già
  posseduto (relink ping-pong tra due file stesso artista+titolo); `attach_local_file`
  non salva mtime/size (re-hash inutile al run dopo) e niente guardia sui possessi
  duplicati stesso hash/path.
- **E8 · Path config con `~` non espansi** — slskd "configurato" ma ogni download
  fallisce in silenzio; `field_validator` con `expanduser` sui 4 campi path.
- **E9 · ilike usato come match esatto senza escaping** (%/_ wildcard) in dedup
  import, riaggancio indice, lookup DjOrganizer → helper `ci_equals` condiviso.
- **E10 · Varie**: `/api/transitions` ricalcola ogni score 2 volte su tutta la
  libreria; GET /api/pipeline fa 2 walk completi del filesystem a ogni polling della
  dashboard (cache TTL); `file_search` materializza+ordina l'intero albero a ogni
  battuta; risposte ambigue di generate-async e del path cached di mix_identify
  (`accepted`/stato di un altro job); `_explain` del Discovery senza Pydantic
  (regola 6, unico punto non conforme); soglie rischio duplicate scoring/generator;
  stato traccia 'enriched' documentato ma mai assegnato; `backfill_labels` con
  `remaining` che non converge mai (invito a ricliccare all'infinito).
