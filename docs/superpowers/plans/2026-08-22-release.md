# ④ Rilascio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Un `.dmg` che si può mandare a qualcuno, con accanto le istruzioni che gli servono per aprirlo.

**Architecture:** Nessun codice nuovo. Una licenza che il bundle già richiede, un target di build dichiarato invece che ereditato, e la documentazione che manca a chi riceve il file.

**Tech Stack:** Tauri v2 (`bundle.targets`), Markdown.

Spec: `docs/superpowers/specs/2026-08-22-release-design.md`.

## Global Constraints

- **Inglese** in `README.md`, `docs/*.md` e `PROGRESS.md`; italiano nel codice.
- **Non affermare che l'app è notarizzata o firmata da Apple**: non lo è, e non può esserlo senza l'account.
- **Non suggerire `xattr -dr com.apple.quarantine`**: disattiva un controllo di sicurezza, e insegnarlo a chi non sa cosa fa è un cattivo servizio.
- **L'updater automatico è fuori ambito** e va dichiarato tale, non lasciato intendere come fatto.
- Build: `export PATH="$HOME/.cargo/bin:$PATH"`, poi `python3 src-tauri/scripts/assembla.py`.

### Task 3: Le istruzioni per chi riceve il file

**Files:** Modify `README.md`

- [ ] Una sezione che dica, in quest'ordine: **cosa succederà** (il primo tentativo fallisce e il messaggio dice «danneggiato»), **che il file non è rotto** (manca la notarizzazione, che richiede un account Apple a pagamento), e **i passi esatti**: aprire il `.dmg`, trascinare l'app in Applicazioni, provare ad aprirla, poi Impostazioni di Sistema → Privacy e sicurezza → «Apri comunque». Precisare che su macOS recenti il clic destro → Apri non basta più.
- [ ] Estendere la sezione «Releases» esistente con la costruzione del bundle, dove esce il `.dmg`, e l'allegarlo alla release GitHub — la stessa che il bottone «Controlla aggiornamenti» già interroga.
